# AutoBattle — 基础作战 + 战术配置

Godot 4.6，2v2 连续移动、真实弹道、对称掩体。双方相同属性和技能池，无 AP / PP 点数。

## 启动与观察

双击 `启动游戏.command`。空格开始/暂停，R 同配置重开；N 或“步进0.2秒”暂停并前进0.2秒模拟时间。
默认展示炮击压制 vs 突击游击。默认0.5×，可切换1× / 2×。所有速度、单步和加速测试统一使用1/60秒模拟步长，不会因为播放速度改变战斗结果。

蓝红两队的下拉框可分别选择七套预设：

- 标记集火：标记手制造机会，队友强射和协同追击。
- 游击牵制：一人压制、后撤，另一人冲刺、绕侧、抓收招。
- 掩护反击：前方防御承压，队友给予护盾并追击。
- 风火连击：风系连续低伤攻击，火系穿透防御。
- 山林守势：山系吟唱重击，林系持续伤害和受伤治疗。

选择角色或点击圆点，在“技能｜条件一｜条件二”修改四主动、四反应。修改立即重开。清空当前角色策略不会让其停止作战；重新选择队伍预设可恢复该队配置。配置仅保存在本次运行，退出后恢复默认。

## 尺度与生命

每格80像素，棋子直径48像素（0.6格），仍连续移动。两处掩体各占1×2整格，按180度旋转对称布局。每台4HP，显示四个血格，所有伤害、护盾和治疗均为整数。

侧闪识别可见敌人的瞄准及飞来的威胁弹道，可取消第一发之前的瞄准；不取消吟唱、已经开始的连发或收招。检查整段1格路径，不能穿人、穿墙或出界。默认风系和林系角色配有侧闪。

## 基础作战

不占策略槽，八槽全空也能自动完成战斗：

1. 发现目标且能射击时，进行一发普通射击。武器恢复时保持射位。
2. 已知目标被遮挡或超出射程时，寻路到可射击位置。
3. 失去视野后，先前往最后发现的位置；记忆过期或到达后巡查交战区域。
4. 遇到移动单位主动绕行；掩体和硬边界不可穿越。

基础行为在没有可用主动策略时接管。不会把“强射仅攻击标记敌人”误解成“没有标记敌人就不能普通攻击”。视野由队友共享；不读取不可见敌人的实时位置来追踪。

## 原有十个战术技能

| 类型 | 技能 | 效果 | 冷却 |
|---|---|---|---|
| 主动 | 标记弹 | 单发1伤害，命中标记5秒 | 3秒 |
| 主动 | 强力射击 | 单发2伤害，已标记目标额外1 | 2.6秒 |
| 主动 | 压制射击 | 单发1伤害，命中减速40%，持续2.4秒 | 3.5秒 |
| 主动 | 绕侧 | 侧向移动1秒 | 3秒 |
| 主动 | 后撤 | 远离目标移动1秒 | 3秒 |
| 主动 | 短冲刺 | 快速接近0.5秒，收招0.45秒 | 3秒 |
| 反应 | 侧闪 | 被瞄准时横移1格、耗时0.4秒，无无敌帧 | 2.8秒 |
| 反应 | 架枪防御 | 被瞄准时停步0.6秒，0.8秒内每次直击减伤1点 | 3.5秒 |
| 反应 | 掩护队友 | 队友被瞄准时给予1点护盾，持续2秒；距离≤3格且无遮挡 | 4.2秒 |
| 反应 | 协同追击 | 队友命中后0.8秒内启动一次1伤害射击；必须有视线和射程 | 3秒 |

悬停技能菜单可查看说明。追击的命中不会触发新的追击，避免连锁。反应可取代移动动作，但不取消射击、收招；结束后重新判断局面。短冲刺无无敌帧，不穿人或掩体。

基础射击每轮一发、1伤害；风系两发间隔0.45秒；一般射击收招0.65秒，强射收招1秒。对准且无遮挡才能开火，没有额外瞄准倒计时。

## 躲招与收招反打

基础行为不占策略槽：观察可见敌人的锁向蓄力、固定霰弹轨迹、公开落点与可见来弹。蓄力预警有0.12秒观察延迟，不读取敌人后续决策。按实际碰撞形状、移动速度和剩余时间选择安全落脚点，同时排除墙、边界、其他单位与其他攻击区域；优先少走路且保留射程/视线的位置。安全后停止逃跑。

配置了侧闪且条件、冷却允许时，使用高速位移；否则尝试普通走位。躲开后短暂关注原攻击者，安全时等待其结束蓄力，进入收招后尝试普通射击反打，不重置武器冷却。界面显示“规避预警 / 观察蓄力 / 收招反打”。已经承诺的动作不能撤销，因此不是必躲或必反击。

`--evasion-test` 验证无PP走位躲光束并在收招期间命中、已经安全不乱动、重叠落点规避、收招不能免费取消。完整对局报告中的“收招反打”计数是启动次数，不等于命中次数。

## 新增攻击形态

- **蓄能贯穿**：起手锁方向，蓄力1.1秒后瞬发，直线2点真伤。提前显示14像素宽的命中带；穿人、不穿墙。冷却5秒。
- **霰弹**：锁方向准备0.45秒，发射5枚固定扇形弹丸，每枚1伤害。弹丸有飞行时间，显示扇形和五条弹道，近距离可能同时中多枚。冷却3.8秒。
- **抛射轰击**：锁定三个固定散布落点，准备0.55秒、飞行0.95秒，三个半径0.5格的圆各造成1伤害。圆圈显示落点、进度，落点不追踪、不随机。起手仍需可见射程内目标，之后抛射越过墙体，从上方覆盖完整圆形范围，墙体不遮挡爆炸；身体接触圆圈即命中。冷却5.5秒。

全部在主动槽可选，原有技能保留。新增炮击压制、突击游击预设。技能范围开关控制预警；实际弹丸和命中特效保留。基础作战会在空闲、移动或尚未开火的瞄准阶段规避预警；已承诺的吟唱、连射、收招与架枪防御不能取消。

## 八个元素技能

仍使用主动/反应槽，不新增AP/PP点数。当前没有独立常驻护甲数值，火系的穿防体现在无视架枪防御的1点减伤；护盾照常吸收，掩体照常阻挡。

| 系别 | 主动技能 | 反应技能 |
|---|---|---|
| 风 | 风刃：2发×1伤害，逐发对准，冷却3.2秒 | 追风：队友命中后2发×1伤害，冷却3.5秒 |
| 火 | 火矢：1真实伤害，冷却3.4秒 | 焰返：被瞄准后向攻击者发射1真实伤害，冷却4秒 |
| 山 | 落岩：吟唱0.6秒，单发2伤害，冷却4.5秒 | 震山：被瞄准后吟唱0.45秒，单发2伤害，冷却4.5秒 |
| 林 | 荆棘：命中附加荆棘，每2秒1伤害、持续4秒，冷却4.5秒 | 回春：自己/附近队友受到生命伤害后0.8秒内，治疗最低血量者1HP，冷却5.5秒 |

山系射击收招1秒，吟唱期间有范围与进度提示，不能被自己的反应取消。林系荆棘不叠层，重复命中刷新持续时间；持续伤害受护盾吸收，不受直击防御影响。回春范围3格、需视线，不复活、不超过4HP，菜单只提供可用于治疗的条件。追风和协同追击都不会触发新的追击链。

风/火/山/林弹道分别为浅蓝、橙、土黄、绿。绿色荆棘环显示持续伤害，绿十字显示治疗。

## 条件与反馈

条件包括血量、标记、敌人收招、近/远距离、攻击队友、队友被瞄准、自己被两人瞄准，以及优先队友目标、低血量、最近敌人。
先检查限定条件，再按条件一、条件二处理偏好；没有偏好对象仍可选其他合法对象。技能的事件、冷却、射程检查不占条件槽。

- 金圈：标记；紫圈：减速；青色外环与盾条：队友护盾；淡蓝填充：自身防御。
- 青色连线：掩护；绿色连线：协同追击。
- 触发规则短暂高亮；选中角色显示当前动作、主动规则未执行原因及状态时长。
- 枪口闪光、后坐、弹迹、收招进度和两行动作标签用于观看。

消灭对方两人获胜，同时全灭或60秒超时判平。18–42秒硬边界收缩。

## 验证与限制

运行 Godot 时添加用户参数：

- `--blast-test`：墙内落点与墙外身体擦边、相切/圈外、预警与爆炸结算、无重复伤害、护盾/防御和AI几何一致。
- `--pattern-test`：锁向瞬发/墙体遮挡、五发弹丸、落点延迟结算、14场新预设对局，输出 `reports/pattern-validation.json`。
- `--readability-test`：整格掩体、棋子尺寸、实弹闪避对照、整数HP与10场对局边界检查。输出 `reports/readability-validation.json`。
- `--magic-test`：多段次数、山系吟唱、穿防但不穿盾/墙、两次持续伤害、治疗与距离、追风不连锁，以及20场魔法预设对局。输出 `reports/magic-validation.json`。
- `--content-test`：空策略完整对局、最后位置搜索、护盾范围和吸收、减速命中、追击不连锁、三种播放速度一致、单步、三预设九种配对各交换出生侧，共18场。输出 `reports/content-validation.json`，包含十技能实际触发次数。
- `--rules-test`：编辑回调、限定与偏好、反应冷却、空策略兜底与完整对局。
- `--aim-test`：朝向、立即射击、点射追踪、掩体遮挡。
- `--boundary-test`：四边、缩圈、掩体交界。
- `--movement-test`：大碰撞体相向交叉走位，无敌人也能绕开彼此。

`加速统计.command` 测默认两队，扰动出生位置并交换出生侧，写 `reports/rules-batch.json`。历史胜率不代表当前内容版。上述18场用于功能覆盖，并非平衡统计；仍需试玩评估打法多样性、出生侧影响与地图观感。

实现：`scripts/battle.gd`（模拟、UI、验证），`scripts/tactics.gd`（技能目录、条件、七套预设）。


## Git 版本存档

本地分支 `main`，初始版本标签 `prototype-before-ap-pp`：已有弹道、蓄力、炮击、智能规避和爆炸擦边修复；尚未按新讨论的 AP 主循环／事件触发 PP／基础槽最低优先级进行整理。

回到这一版并继续实验，可在保存当前改动后，从标签创建一个分支：

```sh
git switch -c revisit-prototype prototype-before-ap-pp
```

返回主线：

```sh
git switch main
```

切换前先用 `git status` 检查，未提交改动应先提交或暂存，避免跨分支携带改动。分支名已存在时直接 `git switch revisit-prototype`。本仓库仅本地保存，未配置远程备份。历史统计和截图随初始版本留存，不代表当前代码的全部验证结果。
