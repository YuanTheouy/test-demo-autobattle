# 8×8 节拍战斗实验

分支：`codex/beat-grid-combat`。默认入口为 `beat_arena.tscn`；连续版入口 `main.tscn` 保留。两者共享策略编辑界面和机甲绘制，战斗规则分别执行，不把连续坐标判定混入格子模式。

## 要验证的体验

玩家能在暂停时预测“下一拍在哪个格、什么时候能攻击、能不能插入侧闪”，再通过修改少量策略验证自己的判断。先验证规则可读性；技能数值和预设强度是试验初值。

## 位置、姿态与时间

- 8×8棋盘，四邻移动。位置始终是一个整数格；棋子模型的位置、阴影和特效不参与命中。
- 全场共用节拍。以原0.5倍速作为新的默认1倍速：实际每拍0.5秒；新0.5倍每拍1秒，新2倍每拍0.25秒。内部每拍仍推进0.25逻辑秒，每个bot独立推进，改变观看速度不会改变规则或结果。N前进1拍，Shift+N前进4拍；单拍演出也遵循新基准与所选倍速。
- 只有两种姿态：**站稳**和**移动**。移动姿态记录上下左右的趋势。姿态与当前动作独立：移动姿态下可以原地射击，但该拍不会同时跨格。

| 拍末 | 位置 | 姿态 | 本拍执行 |
| --- | --- | --- | --- |
| 0，初始状态 | A | 站稳 | 无 |
| 1 | A | 向左移动 | 起步准备 |
| 2 | 左侧B格 | 向左移动 | 跨格 |
| 3 | B | 站稳 | 执行“站稳” |

因此，从站稳到相邻格重新站稳是**3拍**。同向移动趋势下，下一次跨格只耗1拍；改变方向需要重新准备1拍，再跨格。已经起步的移动会先完成跨格，期间PP侧闪可取消；不会在第二拍被AP“站稳”抢走。停下来不会自动恢复站稳，必须有“站稳”规则。

高级技能：抛射轰击、烈焰爆破、蓄能贯穿、裂地冲击和指挥官大招。它们必须在站稳时起手。低阶技能可以在移动姿态使用，第一版不额外添加站稳增伤。

含高级技能的预设会增加可编辑的“站稳 / 移动姿态 / 有射位”规则。该规则可删除、排序或改条件。新增四个定向移动AP便于实验；接敌和调整站位继续自动选路。当前试验全局可见，因此“搜寻”不在已有目标时强行启动。

## 攻击与PP

AP按优先级选中一次动作，选中拍执行其第一拍，随后完成该动作。每个bot每拍最多选中一条AP或PP；动作结束拍不会再起手另一动作。

| 攻击 | 前摇 | 释放硬直 | 后摇 | 生效方式 |
| --- | --- | --- | --- | --- |
| 普攻、标记弹、火矢等低阶单发 | 1拍 | 1拍 | 1拍，强射2拍 | 释放后1拍命中锁定格 |
| 风刃、追风 | 1拍 | 2拍，逐拍释放 | 1拍 | 每发延迟1拍 |
| 疾风连刃 | 1拍 | 3拍，逐拍释放 | 1拍 | 每发延迟1拍 |
| 落岩、震山 | 2拍 | 1拍 | 2拍 | 释放后1拍命中锁定格 |
| 抛射轰击 | 2拍 | 1拍 | 2拍 | 延迟2拍，十字5格 |
| 烈焰爆破 | 2拍 | 1拍 | 2拍 | 延迟2拍，3×3共9格 |
| 蓄能贯穿 | 3拍 | 1拍 | 2拍 | 释放拍，上下左右直线最多4格 |
| 裂地冲击 | 2拍 | 1拍 | 2拍 | 释放拍，上下左右直线最多4格 |
| 霰弹 | 1拍 | 1拍 | 1拍 | 延迟1拍，前方4格，每个目标最多受伤一次 |

范围在起手时锁定并显示。结算时按最终所在格检查，不追加身体半径，也不追踪移动目标。直线技能须有对齐的目标才起手；抛射范围可越过掩体。

### 方格预警

每个被锁定的格子有暗色完整方框，面向玩家的左下斜边显示连续填亮的进度；每一段对应一拍，总共N拍就分成N段、切N−1刀。一拍不切、两拍切一刀、三拍切两刀。格内数字显示距最近一次落下还剩几拍。最后一拍提高亮度，实际生效拍整框亮起并短暂显示“落下”，空格落空也使用这一文字。

进度以攻击起手拍为起点、实际落下拍为终点，覆盖剩余前摇和飞行；释放时不重新计时，也不改变分段数。一拍填满一段，段内连续播放；已经填亮的段保留，数字逐拍递减，落下闪亮时也沿用相同分段。单拍延迟填满无切线的整条边。连发优先显示下一发的计时；同阵营多个攻击重叠时取最早落下的一次，双方重叠时用内外两层边与各自数字区分。颜色沿用蓝方蓝紫、红方橙红。

前摇取消或施法者死亡会撤去尚未释放的预警；已发出的攻击仍保留。暂停冻结进度，倍速随观看速度缩放；单拍播放结束、下一拍尚未结算时保留末端小缺口，整框亮起只对应实际生效。关闭“范围预告”隐藏预警，不隐藏真实落下特效。预警数据由 `beat_telegraph.gd` 从规则快照推导，连续填充不改变命中拍或范围。

PP侧闪在每拍决策前检查：

- 前摇：取消攻击，退还本次精力，再支付20精力侧闪。
- 释放硬直：不能插入，连发整段都属于硬直。
- 后摇：取消剩余后摇，不退款，原攻击CD及已发出的攻击保留。
- 侧闪用1拍进入安全相邻格，结束后保留移动趋势，下一拍重新决策；不获得无敌帧。
- 没有威胁、安全格或资源时不取消。退款可用于支付侧闪。
- 其它PP在动作空档执行，支援有1拍后摇，攻击型PP使用相同攻击阶段。协同追击只响应上一拍的队友命中，不对同一事件排队重试。

独立技能CD从实际释放开始，公共CD从最后一发开始；原秒数向上取整为整拍。技能起手时扣精力，等待和普通移动每拍恢复3。减速期间普通跨格额外等待1拍，侧闪不受影响。

## 小整数生命与技能数值

所有bot初始5血。生命、伤害、治疗和护盾均使用整数，最小有效单位为1，不保留隐藏的小数生命。血条显示五格，角色卡同时显示剩余血量和护盾；精力仍沿用100点，以保留现有起手与侧闪退款规则。

| 技能 | 单次伤害或效果 |
| --- | --- |
| 普通攻击、标记弹、压制射击、协同追击 | 1伤害 |
| 火矢、焰返 | 1真实伤害 |
| 风刃、追风 | 每发1伤害，共2发；分两拍释放 |
| 疾风连刃 | 每发1伤害，共3发；分三拍释放 |
| 强力射击 | 2伤害；目标已有标记时额外1，共3 |
| 落岩、震山 | 2伤害 |
| 霰弹 | 每个被覆盖目标1伤害；同目标不重复计算 |
| 抛射轰击、裂地冲击 | 2范围伤害 |
| 蓄能贯穿、烈焰爆破 | 2范围真实伤害 |
| 天穹贯穿 | 3直线真实伤害 |
| 星火轰炸 | 2范围伤害；重叠区域同目标只结算一次 |
| 荆棘 | 命中不直接扣血；之后每8拍扣1，共2次；不叠加，架枪不能减免 |
| 回春 | 恢复1血，上限5；满血不触发 |
| 灵木护佑 | 恢复1血并获得1护盾，盾持续8拍 |
| 掩护队友 | 提供2护盾，持续8拍；取现有盾与新盾的较高值，不累加 |
| 架枪防御 | 持续4拍，每次物理直击减伤1，最低0 |
| 敌方碰撞 | 各扣1血；友军碰撞不扣血 |

真伤无视架枪减伤，但护盾能吸收。护盾同样吸收碰撞和持续伤害。标记持续20拍，压制减速持续10拍；本拍新标记不增强同拍强射。低血量条件统一为“自己HP≤2 / 队友HP≤2”，旧预设条件自动迁移。普通攻击五次命中即可击倒满血目标；强射配合已有标记可打3血，再接一次2伤害即可击倒。各技能的范围、节拍与连续动画保持既有规则。

## 抢格碰撞

碰撞发生在**实际跨格拍**，下一拍弹回；不额外添加隐藏的准备拍。

- 多个bot同拍进入同一个格：该拍暂时共同占格，发生一次碰撞。存在敌方时，每个参与者受到1点碰撞伤害；纯友军碰撞无伤害。
- 第三名bot加入也只造成每人一次1伤害，不按两两组合重复扣血。
- 下一拍强制返回各自出发格，不能插PP或AP。原格在碰撞及返回期间保留，其他移动不能抢占。
- 碰撞拍的范围攻击可以命中该格的全部参与者。
- 对向交换相邻格会在边上碰撞，各自留在原格，下一拍完成弹回。禁止穿过对方。
- 碰撞会中断原动作，不退还攻击精力。已在本拍释放的攻击仍生效。

## 每拍的固定结算顺序

1. 保存所有角色和已公布攻击的同一份拍首快照。
2. 推进资源和状态计时；所有bot独立选PP、推进旧动作或选AP。
3. 汇总移动提案，统一处理抢格、对向碰撞、返回格保留和弹回。
4. 应用本拍治疗、护盾和防御。
5. 以移动后所在格收集到期攻击和碰撞伤害，统一扣血。
6. 应用新标记、减速、荆棘等效果；它们不改变同拍其它攻击的判定。
7. 统一判断死亡和胜负，保存拍末状态。

界面显示拍末所在格、姿态和趋势；“待释放”等阶段表示下一拍将推进的阶段。战斗记录和右侧详情标出本拍分支和规则触发次数。

## 试验范围

### 连续演出

判定按每拍0.25逻辑秒的整拍快照推进，默认每拍用0.5真实秒播放，画面每个渲染帧更新。`beat_presentation.gd` 单独保存显示位置、朝向、动作过渡及特效时间，不回写战斗数据。

每次结算产生新的动作目标，随后在一拍时间内连续演出：准备时身体向移动方向倾移，跨格时连续通过格间，站稳时回到格心；侧闪带残影，碰撞接近后在下一拍连续弹回。朝向、影子、血条、遮挡和点击选中跟随显示位置。前摇蓄力圈、释放后坐力、弹丸飞行和命中特效按连续时间播放，弹丸只飞向已锁定的格子。

移动段同时衔接位置和速度，使用三次Hermite曲线：起步逐渐加速，同向连续跨格保持每拍80像素，即320像素/逻辑秒、新基准1倍速下160像素/真实秒，不在每个格心减速；站稳、攻击或转向时接住已有速度并缓冲，站稳的缓冲限定在当前格内。身体起伏的幅度随显示速度变化。逻辑节拍与动画使用同一个时间累积器，在跨拍边界先完成旧段，再结算并接入下一段，避免物理更新与渲染更新错位造成停一帧；判定仍为固定0.25逻辑秒，不随显示帧率改变。

位移引导由绿色虚线、箭头、目标小圆圈及“目标格 / 下拍进入、跨格或侧闪”文字构成。小圆圈半径10世界像素，表示移动目标点，不再使用四角框或整格目标填色。碰撞后的返回引导使用金色，明确标出返回格和“下拍弹回”。只显示当前已经选中的移动，不推测后续路线；站稳或攻击后清除旧目标。关闭攻击范围预告不影响移动引导。

每个存活bot的实际逻辑格显示阵营色四角框、淡底色、近侧姿态边与脚前固定名牌，例如“蓝1 D4 / 站稳”“红1 E4 / 移动·右”。四角框沿用原绿色移动目标框的造型，但改为蓝红阵营色，用于区分当前位置与绿色圆圈目标。站稳使用完整底边、两端短脚和金色小方块；移动使用两端留空的短底边与绿色方向箭头，不画四边虚线。姿态同时以形状、图标和文字区分。地面标记、名牌、连线及攻击预警均在角色和掩体之前绘制，允许被自然遮挡，避免盖住角色。标记从 `cell / pose / trend` 生成，每拍直接更新，不跟随身体插值。身体动画偏离格心时有细线连回逻辑格，机甲上方另显示当前动作阶段。碰撞时共同占格的bot分别显示名牌与错层角框，不覆盖成单个标记；死亡后撤去位置标记。关闭攻击范围预告不隐藏位置和姿态。

移动姿态不等于这一拍正在跨格：在该姿态下原地攻击或等待时仍显示“移动·方向”；实际动作看机甲上方阶段和位移引导。右侧格子、血量和日志也直接显示本拍结果；身体正在演出这次已结算的变化，因此可能暂时处在两个格子之间。演出中的坐标和弹丸不会参与命中计算。暂停冻结动画；单拍按钮只结算一拍，再播放完该拍的动作。倍速同时缩放节拍间隔和演出时长。

当前为规则与演出原型：固定整格掩体、全局可见、没有连续击退或身体碰撞。手动大招也按格预览并在合法节拍起手，需要站稳和70精力；前摇侧闪取消会返还充能。采用5血小整数数值，保留精力、共享12条规则、布阵保留和九种预设。这些是第一版数值，尚未完成强度平衡；240拍超时平局，不用总血量掩盖战斗中的僵持。

## 运行和验证

在Godot运行项目即进入节拍版。运行 `main.tscn` 可对照连续版。

```powershell
Godot --headless --path . -- --beat-test
Godot --path . -- --beat-preview
Godot --path . -- --beat-animation-preview
Godot --path . -- --beat-telegraph-preview
Godot --headless --path . res://main.tscn -- --lifecycle-test
```

`scripts/beat_simulation.gd` 是不依赖绘制的规则引擎；`beat_battle.gd` 复用配置UI；`beat_view.gd` 绘制格子范围和趋势。验证覆盖3拍移动、惯性与转向、姿态门槛、AP/PP互斥、侧闪退款、多人碰撞、退路保留、反向更新顺序、六组对称用例、九种预设、倍速及编辑器操作。报告位于 `reports/beat-validation.json`，界面位于 `reports/beat-preview.png`。

动画验证同时检查过渡起点连续、半拍中间位置、整拍终点、侧闪残影、射击消退、暂停、单拍和不同渲染频率；每次确认显示更新未改变战斗快照。`reports/beat-animation-preview.png` 展示跨格、碰撞、弹回三个动作各自0/83/167/250毫秒的画面。

报告 `motion` 字段另验证跨拍位置与速度连续、连续同向跨格无减速、站稳缓冲不越格、引导目标与已选动作一致；30/60/144 FPS与0.5/1/2倍速下，逻辑结果、显示位置、速度和拍内进度一致。

报告 `occupancy` 字段验证起步与跨格时逻辑格切换、动画中标记锚点稳定、移动姿态原地施法时不误标为站稳，以及共同占格的多bot标签和死亡撤标。

`beat_balance_validation.gd` 验证全部攻击的实际总伤害、五次普攻击倒、物理减伤与真伤、护盾吸收、荆棘两次跳伤、满血治疗门槛、队友护盾和低血量条件迁移。结果合并在 `beat-validation.json` 的 `balance` 字段。

`beat_telegraph_validation.gd` 对照实际释放和命中拍验证普攻、光束、抛射、两连发及三连发的计时；覆盖取消、施法者死亡、重叠攻击、单拍预警及暂停，结果位于报告的 `telegraphs` 字段。`beat-telegraph-preview.png` 展示从前摇到飞行再到落下的方框进度。
